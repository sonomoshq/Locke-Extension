# Browser/native recovery follow-up, 2026-09-05

This is executable regression evidence, not native clean-machine acceptance.

## Reproduced failures and changes

- A capture deadline abandoned `sendNativeMessage` without owning a cancellable browser port. Health checks had the same problem. Both now use an independent `connectNative` port per request, remove listeners and close it on response, error or timeout. Captured requests are never retried automatically.
- A session-storage health lock survived worker eviction. A popup check could then return the previous connected/Active result without contacting the host. Concurrent checks also raced through the non-atomic storage lock. One worker-local Promise now coalesces checks and gives every caller the same live result. Popup capture-evidence changes during a running check invalidate its result and queue a fresh follow-up, so older evidence cannot restore Active.
- Worker evaluation repaired a missing presence alarm but left a missing health alarm absent indefinitely. It now repairs both without restarting an existing countdown.
- The popup displayed cached Active while a restarting worker failed to answer. It now starts at Checking, bounds its wait, and gives specific reload/retry guidance on worker failure. Desktop component protocol mismatches give update/repair guidance.
- The native host retained detached capture tasks after browser EOF. It now owns and cancels those tasks and its reply writer when the browser port closes or output fails.
- The native host accepted a decodable receipt or status with any application envelope version. It now rejects mismatched versions before using the payload. Same-version additive fields and legacy absent probe fields retain their existing safe behavior.

## Checks

`npm test`: **523 passed**, including 46 service-worker tests, five native-port tests and three popup tests. Missing host, policy-disabled registration, timeout/recovery, Firefox disconnect error, listener cleanup, concurrent calls, worker wake and stale popup scenarios use browser API fixtures. The new stale-lock, concurrent-probe, lost-alarm, port-ownership and popup assertions failed before their fixes.

Native host: `cargo test --manifest-path native-host/Cargo.toml --locked`: **39 passed, 11 failed**. All 11 failures are the existing native filesystem-socket fixtures: this runner rejects `bind` with `Operation not permitted`. The framed in-memory bridge tests pass (12); EOF cancellation and sequential native-port exchanges also pass. Restoring the old wait-for-capture shutdown behavior makes the cancellation test fail on its deadline; accepting arbitrary envelope versions makes the mismatch test fail.

## Native acceptance still required

Exercise Chromium and Firefox native registration on supported operating systems, desktop stop/start, native-host crash/restart, browser and extension updates, and a real mesh restart while a capture is held. The fixture tests do not prove browser process termination or clean-machine installation. Captures already handed to the screening mesh retain its existing bounded processing deadline; this change does not introduce a distributed cancellation protocol or replay captured content. Surface catalog, host permissions and disabled-host semantics are unchanged.
